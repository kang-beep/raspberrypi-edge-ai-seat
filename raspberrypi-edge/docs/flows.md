# Edge 운영 흐름과 예외

## 1. 사용자 첫 등록

1. 대시보드에서 사용자 이름 입력 후 등록 시작
2. PC → MQTT로 Edge에 촬영 요청
3. Edge 웹캠 활성화
4. **YuNet**으로 얼굴 탐지 및 crop
5. **SFace**로 임베딩 추출
6. 사용자 계정 + 임베딩을 PC DB에 저장

> 잘못된 이해 주의: crop은 YuNet, 특징 추출은 SFace입니다.

## 2. 예약 후 입장

1. 사용자가 해당 시간대 좌석을 예약
2. 초음파 센서로 착석 감지
3. 웹캠 활성화
4. YuNet 탐지 → SFace 임베딩
5. 예약된 userId 임베딩과 코사인 유사도 비교
6. 일치하면 `occupied`, 불일치/실패면 거부 이벤트 전송

## 3. 자리 이탈

1. 착석 중 센서가 이탈 감지 → `short_away`
2. `shortAwayGraceMinutes` 동안 복귀 없으면 → `away`
3. `awayGraceMinutes` 동안 복귀 없으면 → 점유 취소 후 `empty`

복귀 시(센서 재감지 + 필요 시 재인식) `occupied`로 복원합니다.

## 예외 상황

| 예외 | 처리 방향 |
| --- | --- |
| 예약 없이 착석 | 입장 거부 또는 관리자 알림. 자동 occupied 금지 |
| 얼굴 불일치 | 좌석 미승인, 경고 이벤트, 카메라는 타임아웃 후 종료 |
| 착석했지만 얼굴 미검출 | 재시도 N회 후 실패. 무한 대기 금지 |
| 센서 오탐(착석/이탈) | 연속 샘플 확인(디바운스) 후 상태 변경 |
| MQTT 끊김 | Edge는 로컬 버퍼링, 재연결 후 상태 동기화 |
| 예약 노쇼 | 예약 시작 후 M분 미착석 시 예약 자동 취소 |
| 중복 예약 | 서버에서 시간대 충돌 검증 |
| 한 프레임 다중 얼굴 | 가장 큰/중앙 얼굴만 사용하거나 실패 처리 |
| 유예시간 중 잠깐 복귀 | occupied 복귀, 유예 타이머 리셋 |
| 카메라/모델 오류 | 장치 degraded 상태 보고, 좌석은 unknown이 아니라 직전 상태 유지 + 알림 |

## MQTT

- Broker: EMQX Cloud (TLS 8883)
- Edge: MQTT client만 사용 (Broker를 Pi에서 띄우지 않음)
- 토픽/페이로드: [mqtt.md](./mqtt.md)
- 계정: `.env` (예시: `.env.example`)
- Device ID: `raspi-a{n}`
